# Ideate

You are the operator's hands on a box with `bmesh`: the chat is the interface, so run the command and say what happened. `bmesh ideate` does the checking (a ship row, fewer than five proposed specs, no round of the repo still open, a level `main`, reachable hosts); do not redo it, relay its refusal. A round still open is the operator's to wait for; pass `--force` only when they say to start another beside it.

**Only the operator starts a round.** Run `bmesh ideate` only when the operator, in this chat, asked for a round on a repo. A subagent, a reviewer, or a thread asked to review, critique or read a spec or an idea never runs it, nor `bmesh build`, nor anything else that starts a thread: it reads and reports.

**A round or one idea: decide by what was asked, not by the words.** `bmesh ideate <repo>` always starts two threads, an engineer and a UI/UX engineer, and each proposes three to five ideas of its own. That is a **round**, and only an open question gets one: "proposals for X", "run a round on X", "what would you improve in X". When the operator names one specific thing they want, however they put it ("ideate this idea: ...", "spec this", "write this up", "I want to work on ...", "spin up an ideate thread for ..."), it is **one idea**, and never a round: a round would add a UI/UX thread nobody asked for, and both threads would propose around the idea instead of writing it. When it is unclear which, ask in one line before starting anything, since a round can't be taken back without stopping two threads. One idea goes one of two ways.

- **As one engineer thread**, when the operator asks for a thread, names a model or an effort, or the idea needs the repo read and measured at length: `bmesh ideate <repo> --idea [--model M] [--effort E] --context -`, with their words on stdin, on the row's `host` as step 1 says (the thread always runs there). It starts only the engineer, and its brief replaces the round's three to five specs with that idea's spec (one half-pager, or two or three in build order). Steps 1 to 6 then apply, and the pitch is that idea's specs.
- **Here, in this session**, otherwise: write that idea's spec yourself, following `ideate-engineer` sections 1 to 4 for the one idea: read the repo and its ledger, measure, widen and attack the idea, then write the half-pager (`bmesh spec template`, its id claimed with `bmesh spec next-id` (`--count N` for two or three) and then landed, `proposed_by: operator`, `status: proposed`). An idea too big for one lead becomes two or three specs in build order, each naming the one before. Ask the operator only what the repo can't settle. Before writing, when a grilling skill is installed in this session (one named like `grill-me`), offer it in one line: being grilled on the idea first is the operator's call, and a no goes straight to the spec. Feedback a build's leads left is not the operator's idea: the `build` skill writes those specs and offers no grilling. Land it as `ideate-engineer` section 5 does, from a worktree of your own when the main checkout isn't clean on `main`: commit `Propose NNN: <title>`, fast-forward `main`, push. Report one line per spec, `NNN title (kind, size, judge): why it matters`, and end with: the spec is on main as `proposed`, and the operator's review of it is `buildermesh:choose-ideas`. Steps 1 to 6 below are for a round and an idea thread, never for an idea written here.

1. **Where it runs.** `bmesh repos show <repo> --json` gives the row; its `host` is where the round runs. When `host` is this box (`hostname -s`, lower case), run it here. Otherwise run it there: `ssh -o BatchMode=yes <host> "bash -lc 'bmesh ideate <repo> [--idea] [--model M] --context -'" <<'EOF'`, the operator's words on the lines after it and `EOF` last (ssh joins its arguments into one remote command line, so the inner command is quoted twice, and ssh forwards stdin). When that host can't be reached from here, say so and stop: nothing is started.
2. **The command.** `bmesh ideate <repo> [--idea] [--model <m>] [--effort <e>] [--context -]` (`--model` only when the operator named one). Whatever the operator asked beyond the repo's name (focus areas, what to weigh, how the specs are to be checked) goes in `--context` in their words, always on stdin through a quoted heredoc (`--context - <<'EOF'`), never inline, so quotes and `$` in their words stay as written. Each started thread reads it in its brief. When they asked nothing more, leave `--context` off (an idea thread always has it); never ask for focus or make it up. Never start a round and then send the words to the threads' inboxes instead: a thread reads its inbox only at a checkpoint. It prints one JSON line: the round's `path` and, under `eng` and `ux`, each started child's `path`, `thread`, `branch`, `worktree` and `host` (an idea thread has only `eng`).
3. **The Fable fallback.** Rounds run on `[models] proposer` (Opus at `xhigh` by default); this applies only when the operator named a Fable model. When the runner rejects it (an error naming the model, consent or credits) for every child it started, so the round reads `blocked` with no thread started (`bmesh thread-status <repo>-round-<N>`), run the same command once more with `--model claude-opus-5-5` (it opens round N+1; the empty round stays blocked on the mesh) and tell the operator what the runner said. When one child started and the other did not (exit 1, `round <path>: the ux thread did not start: ...`), never rerun: a second round would propose under the same spec ids. Report the started thread (`bmesh mesh-status --json`, the child node's `runner.thread`) and the blocked one with the runner's words; the round settles with the started child's pitch, and restarting the other is the operator's call. Any other failure is reported as printed, never retried.
4. **Report** the round path (`<repo>-round-<N>`, as `bmesh ideate` printed it: `<repo>` is the repo's name in lower case, with `.` and `_` as `-`), each started thread's id with its host and the model (say if it fell back to Opus), and, on exit 1, which child did not start and why.
5. **Watch the round.** `bmesh watch --nodes <the round path> --timeout 30m` follows the round and both children, printing one line per event (`<at> <path> <event> <text>`) and `watch-done` once the round settles `done` or `blocked`; exit 5 is the timeout, re-arm it with `--since <the last line's time>`. Where the harness has a Monitor, arm it on the watch and let it wake you; otherwise run the watch in the background and read its output when it exits. Never poll the runner in a loop. An engineer's `ask` line goes to the operator in its words, the answer back with `bmesh --node operator send <child path> "<answer>"`.
6. **Notify on completion.** When the round's `done` line arrives, tell the operator in this chat: `<repo> round N proposed`, then the ranked pitch as the line carries it. A round `blocked` line is reported with its reason (and the pitch that did arrive).
7. **Stopping a round.** When the operator says "stop the round" (or "stop X", X the round or one of its threads): `bmesh --node operator node stop <the round path> --text "<why>"`, on the row's `host` as step 1 says (a thread on another box is stopped there when that box accepts `stop-thread`). It stops both threads, prints `stopped <child>` for each and `<round> blocked`, and the daemon never wakes them again; a round whose threads were forgotten before it settled is marked `blocked` directly. Never send the threads a free-text STOP message: a message is mail, and mail wakes a thread. Afterwards `bmesh node forget <the round path>` clears the round (and `bmesh node forget <child>` each thread). When the operator says "wipe X" (or to wipe it "as if it never ran"): `bmesh --node operator node stop <the round path> --text "<why>"`, then `bmesh node forget <the round path> --wipe` (`--dry-run` first shows what goes), which removes it and every node under it from the mesh, its brief, worktree and branch; never the `nats` CLI or the mesh token. A thread the operator interrupted in T3 reads `blocked: stopped in t3 by the operator` within a minute and stays stopped; the round then settles `blocked`.

End with one line: the round is started (or proposed, when the watch saw `done`), and what waits on the operator: an unanswered ask, a block, or the review of the pitch (`buildermesh:choose-ideas`). Say what each thing in it is in plain words (a spec or issue by what it does, its number after it in brackets if at all): the line is final and reads on its own, with nothing the operator has to look up.
