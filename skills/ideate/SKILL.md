# Ideate

You are the operator's hands on a box with `bmesh`: the chat is the interface, so run the command and say what happened. `bmesh ideate` does the checking (a ship row, fewer than five proposed specs, a level `main`, reachable hosts); do not redo it, relay its refusal.

**Only the operator starts a round.** Run `bmesh ideate` only when the operator, in this chat, asked for a round on a repo. A subagent, a reviewer, or a thread asked to review, critique or read a spec or an idea never runs it, nor `bmesh build`, nor anything else that starts a thread: it reads and reports.

**One idea is not a round.** When the operator brings one specific idea of their own ("ideate this idea: ...", "ideate this specific idea", "spec this", "write this up"), never run `bmesh ideate`: a round starts two threads that propose ideas of their own around it. Write that idea's spec here, in this session, following `ideate-engineer` sections 1 to 4 for the one idea: read the repo and its ledger, measure, widen and attack the idea, then write the half-pager (`bmesh spec template`, numbered from `bmesh spec next-id`, `proposed_by: operator`, `status: proposed`). An idea too big for one lead becomes two or three specs in build order, each naming the one before. Ask the operator only what the repo can't settle. Land it as `ideate-engineer` section 5 does, from a worktree of your own when the main checkout isn't clean on `main`: commit `Propose NNN: <title>`, fast-forward `main`, push. Report one line per spec, `NNN title (kind, size, judge): why it matters`, and end with: the spec is on main as `proposed`, and the operator's review of it is `buildermesh:choose-ideas`. Steps 1 to 4 below are for a round only.

1. **Where it runs.** `bmesh repos show <repo> --json` gives the row; its `host` is where the round runs. When `host` is this box (`hostname -s`, lower case), run it here. Otherwise run it there: `ssh -o BatchMode=yes <host> "bash -lc 'bmesh ideate <repo> [--model M] --context -'" <<'EOF'`, the operator's words on the lines after it and `EOF` last (ssh joins its arguments into one remote command line, so the inner command is quoted twice, and ssh forwards stdin). When that host can't be reached from here, say so and stop: nothing is started.
2. **The command.** `bmesh ideate <repo> [--model <m>] [--context -]` (`--model` only when the operator named one). Whatever the operator asked beyond the repo's name (focus areas, what to weigh, how the specs are to be checked) goes in `--context` in their words, always on stdin through a quoted heredoc (`--context - <<'EOF'`), never inline, so quotes and `$` in their words stay as written. Both threads read it in their briefs. When they asked nothing more, leave `--context` off; never ask for focus or make it up. Never start a round and then send the words to the threads' inboxes instead: a thread reads its inbox only at a checkpoint. It prints one JSON line: the round's `path` and, under `eng` and `ux`, each child's `path`, `thread`, `branch`, `worktree` and `host`.
3. **The Fable fallback.** Rounds run on `[models] proposer` (Opus at `xhigh` by default); this applies only when the operator named a Fable model. When the runner rejects it (an error naming the model, consent or credits) for both children, so the round reads `blocked` with neither thread started (`bmesh thread-status <repo>-round-<N>`), run the same command once more with `--model claude-opus-5-5` (it opens round N+1; the empty round stays blocked on the mesh) and tell the operator what the runner said. When one child started and the other did not (exit 1, `round <path>: the ux thread did not start: ...`), never rerun: a second round would propose under the same spec ids. Report the started thread (`bmesh mesh-status --json`, the child node's `runner.thread`) and the blocked one with the runner's words; the round settles with the started child's pitch, and restarting the other is the operator's call. Any other failure is reported as printed, never retried.
4. **Report** the round path (`<repo>-round-<N>`), both thread ids with their hosts and the model (say if it fell back to Opus), and, on exit 1, which child did not start and why.

End with one line: the round is started, the ranked pitch arrives as a push (`<repo> round N proposed`) when both threads finish, and the operator's review of it waits on that (`buildermesh:choose-ideas`).
