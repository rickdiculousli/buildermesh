# Quick fix

A change the operator asks to have made is made here, by you, and is done when the repo's definition of done (its `AGENTS.md`) holds. Specs, leads and the ledger are for work the operator asks to have proposed, or to have a lead build; a quick fix uses none of them. So no `bmesh spec next-id` and no file under `docs/proposals/`; no `bmesh ideate`, `build`, `lead start` or `executor new`; no `bmesh land`, `ready`, `done` or `feedback` (those are a node's, and you are none); and no commit that only records state. A request for a spec, a proposal or a thread ("spec this", "ideate this", "write this up", "spin up a thread") is the `ideate` skill's.

1. **Size it** as the definition of done sizes work with no spec: XS one file, S one module, M crosses modules, L changes an interface others depend on. XS, S and M are quick fixes. For L or larger, say in one line what makes it L and offer the two ways, a spec (the `ideate` skill's one idea, built by a lead) or here anyway with a high-effort review, and let the operator choose; a quick fix that grows to L while you make it stops there with the same line. Ask nothing else first: read the code and decide.
2. **Where.** A worktree of your own on a branch from `origin/main` (the harness's, or `git -C <repo path> worktree add <dir> -b <branch> origin/main`), never the repo's checkout itself: a commit there not yet pushed holds every lead's `bmesh land` of the repo until it is, and land fast-forwards that checkout under your edits. It needs a checkout of the repo on this box (`bmesh repos show <repo>` names its path); with none, say so and name the row's `host`, which has one. Never move, reset or push commits on `main` that aren't yours.
3. **Make it**: the smallest change that does what was asked, by the repo's `AGENTS.md` (its engineering rules, and the docs it keeps exact, changed in the same commit). While you work, run the tests the change touches.
4. **Verify.** Commit, then `bmesh routine run verify` in your worktree. It needs no node, records the result for the commit's tree (so the next `bmesh build`'s check that `main` is green reads it rather than running it again) and ends `verify ok|fail t:<tree8>`. In a repo without a `verify` kind, run its verify commands yourself; when `routine run` refuses because the kind runs on another OS, make the quick fix on a box of that OS instead. Fix it until it ends `ok`.
5. **Review by size.** None for XS or S. For M, one review: Opus at medium effort in a fresh session that never saw the change (a subagent where the harness has one), given the operator's words, the diff (`git diff origin/main...HEAD`) and the verify verdict, looking for where the change falls short of what was asked or breaks something, and told to start nothing (no `bmesh ideate`, `build` or `lead start`). Fix what it finds once and verify again; a taste finding (a word, a name, a shape it would have chosen) goes in your report, not in a second pass.
6. **Land.** `git fetch origin`, rebase onto `origin/main`, and when the rebase brought in commits, `bmesh routine run verify` again (it answers at once when none of them touched the code). Then `git push origin HEAD:main`; when it is refused because `main` moved, fetch, rebase, verify and push again. Then bring the repo's checkout level when it is on `main` and clean (`git -C <repo path> merge --ff-only origin/main`), and remove your worktree and its branch.
7. **Release** only when the operator wants the change running now (a hotfix) and the repo is released by tag (`git tag --list 'v*'` prints one): `bmesh release <repo>`, as the `build` skill's step 7 releases (bmesh's own repo writes its upgrade notes first). A `held` or `main is red` refusal is reported, never forced. Otherwise the change waits for the repo's next release, and your report says so.

End as the repo's definition of done ends: one line with what changed, the commit on `main`, its push state from a fresh fetch, the review (`review: none, S`, or what it found and how it was fixed) and what, if anything, waits on the operator, each thing named in plain words.
